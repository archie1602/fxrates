# FX (Foreign Exchange) Rates API сервис

Асинхронный HTTP-сервис валютных котировок на Go. Поддерживаемые валюты: `USD`,
`EUR` и `MXN`.

> **Об AI-инструментах.** `AGENTS.md`, `CLAUDE.md`, `.agents/` и `.claude/` добавлены намеренно: в вакансии отдельно упоминалось владение AI-инструментами,
> и я хотел показать, как настраиваю агентов под конкретный проект.
>

## API ручки

| Метод  | Путь                                  | Назначение                                |
|--------|---------------------------------------|-------------------------------------------|
| `POST` | `/api/v1/quote-updates`               | Запустить фоновое обновление котировки    |
| `GET`  | `/api/v1/quote-updates/{id}`          | Получить состояние и результат обновления |
| `GET`  | `/api/v1/quotes/latest?pair=EUR/MXN`  | Получить последнюю успешную котировку     |
| `GET`  | `/healthz`                            | Проверка состояния HTTP API сервера       |
| `GET`  | `/readyz`                             | Проверка доступности PostgreSQL           |

Полный контракт API приведён в файле [`openapi.yaml`](openapi.yaml).

## Как работает обновление

Обработчик `POST /api/v1/quote-updates` не обращается к внешнему API напрямую. Он
сохраняет запрос в PostgreSQL со статусом "pending" и сразу возвращает клиенту
идентификатор. Фоновые воркеры с заданным периодом вычитывают записи, переводят их в статус
processing, получают курс у Frankfurter API и сохраняют результат вместе со
статусом "completed".

Записи выбираются через `FOR UPDATE SKIP LOCKED`. Эта PostgreSQL конструкция позволяет
нескольким инстансам приложения одновременно работать с одной очередью и не забирать
одну и ту же pending-запись. Вызов Frankfurter выполняется уже после завершения короткой
транзакции с PostgreSQL.

Очередь работает по модели at-least-once: то есть, если процесс остановится после вызова
Frankfurter, но до сохранения результата, запрос к провайдеру будет выполнен
повторно. В целом для текущего сценария это безопасно, потому что используется обычный
GET без побочных эффектов. Идемпотентная POST ручка не создаёт вторую запись, но не
означает, что внешний API всегда будет вызван ровно один раз.

Recovery worker периодически возвращает старые записи из processing в
pending. При каждом захвате PostgreSQL увеличивает `processing_version`, которая служит
fencing token. При завершении воркер передаёт полученную версию, поэтому результат старого
воркера будет отброшен, если задача уже была восстановлена и повторно
захвачена. `PROCESSING_TIMEOUT` дополнительно должен превышать максимальное время всех
попыток обращения к Frankfurter, чтобы активные задачи не восстанавливались преждевременно.

`/healthz` проверяет, что HTTP-сервер работает. `/readyz` дополнительно выполняет
проверку PostgreSQL. На каждый запрос к БД задается таймаут `DATABASE_QUERY_TIMEOUT`.

## Замечания

PostgreSQL тут хранит котировки и одновременно используется как durable-очередь.
Можно было бы передавать запросы на обновление котировки worker-у через обычный
Go-канал, но тогда при перезапуске приложения они бы потерялись. Кроме того, канал работает
только внутри одного процесса, поэтому несколько инстансов приложения не
смогли бы совместно обрабатывать одну очередь. PostgreSQL решает обе проблемы и
позволяет не добавлять в тестовый проект отдельный брокер сообщений.

Запросы к Frankfurter APIшке ретраятся только при сетевых ошибках, ответе 429 и
ошибках 5xx. Между попытками используется exponential backoff с full jitter. Заголовок
`Retry-After` поддерживается в формате количества секунд и HTTP-date. Сервис не делает
повторный запрос раньше указанного времени; если требуемая задержка превышает
`FRANKFURTER_RETRY_MAX_DELAY`, текущая задача завершается с ошибкой.

SQL-запросы, транзакционные гарантии очереди и fencing token проверяются
интеграционными тестами на настоящем PostgreSQL. Тесты используют отдельную БД через
`TEST_DATABASE_URL`; моки PostgreSQL для этих сценариев не применяются.

## Запуск через Docker Compose

Требуются Docker и Docker Compose. Для запуска нужно из корня проекта запустить:

```bash
docker compose up --build -d
```

Compose:

1. запустит PostgreSQL и дождётся его готовности
2. применит SQL-миграции одноразовым контейнером
3. соберёт и запустит API после успешных миграций

API будет крутиться на `localhost:8080`, а PostgreSQL на `localhost:15432`. Внутри
docker compose сети приложение подключается к PostgreSQL по адресу `db:5432`.

Проверить контейнеры и посмотреть логи приложения можно с помощью команд:

```bash
docker compose ps
docker compose logs -f app
```

Пример запроса на обновление:

```bash
curl -i \
  -X POST http://localhost:8080/api/v1/quote-updates \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: 10000000-0000-4000-8000-000000000001' \
  -d '{"pair":"EUR/MXN"}'
```

Заголовок `Idempotency-Key` является опциональным и должен содержать ненулевой UUID.
Повторный запрос с тем же ключом и валютной парой вернёт тот же `update_id`, при этом не
создавая новую фоновую задачу на обновление. Повторное использование ключа с другой
парой вернёт 422 Unprocessable Entity. В случае если заголовок не указан, то каждый запрос создаёт
новое обновление.

Регистр входной пары не важен: `eur/mxn` и `EUR/MXN` обозначают одну пару. Перед
обработкой значение приводится к верхнему регистру, и в ответах используется форма `EUR/MXN`.

Можно скопировать `update_id` из ответа и запросить результат:

```bash
curl http://localhost:8080/api/v1/quote-updates/<update_id>
```

Получить последнюю успешную котировку:

```bash
curl 'http://localhost:8080/api/v1/quotes/latest?pair=EUR%2FMXN'
```

В GoLand JB IDEшке те же запросы можно запускать из файла `api.http`. Сначала надо выполнить
`Create quote update`: обработчик ответа сохранит `update_id`, после чего станет
доступен запрос `Get quote update by the ID saved above`. Чтобы
создать новое обновление, надо поменять значение `idempotencyKey`.

Остановить контейнеры, сохранив данные PostgreSQL можно с помощью команды:

```bash
docker compose down
```

Если данные хочется дропнуть, то можно запустить команду `docker compose down -v`, она остановит контейнеры и удалит volume вместе со всеми
данными PostgreSQL.

Значения Compose по умолчанию предназначены только для локальной разработки.
Их можно переопределить через `.env`; полный список приведён в `.env.example`.
По умолчанию одновременно работают четыре обработчика; параллелизм настраивается через
`WORKER_COUNT` в диапазоне от 1 до 32.

## Локальный запуск

Для запуска без Docker требуются PostgreSQL и CLI
[`golang-migrate`](https://github.com/golang-migrate/migrate).

```bash
cp .env.example .env
set -a
source .env
set +a

make migrate-up
make run
```

## Проверки

```bash
make check
```

Команда запускает быстрые проверки GitHub Actions: OpenAPI-контракт, форматирование,
целостность Go-модулей, `go vet` и unit-тесты с race detector.

Для PostgreSQL integration suite нужна отдельная disposable-база, имя которой
оканчивается на `_test`, и установленный CLI `golang-migrate`. Например:

```bash
export TEST_DATABASE_URL='postgres://fxrates:fxrates@localhost:5432/fxrates_test?sslmode=disable'
make test-integration
```

Команда применяет настоящие миграции из `migrations/` и запускает тесты репозитория с
race detector и отключённым Go test cache. База очищается между сценариями, поэтому
указывать development или хуже того prod-БД нельзя. В GitHub Actions для этих тестов
поднимается отдельный PostgreSQL service container и там дополнительно проверяется цикл
миграций up -> down -> up.

## Структура проекта

```text
cmd/api                              сборка зависимостей и lifecycle
internal/domain                      доменные модели
internal/service                     сценарии и фоновые worker'ы
internal/provider/frankfurter        клиент внешнего API
internal/storage/postgres            PostgreSQL-репозиторий
internal/transport/httpapi           HTTP-маршруты и JSON-контракты
migrations                           SQL-миграции
openapi.yaml                         спецификация HTTP API
.github/workflows/ci.yml             проверки GitHub Actions
.agents                              skill для Codex
.claude                              skill и команда для Claude Code
```
